# 프로젝트 핀볼 — 익명 공 미션 레이스 목업

`index.html`을 브라우저에서 열면 실행됩니다. 설치·빌드·외부 라이브러리가 필요하지 않습니다.

현재 4단계 미션 목록·완료 기준·선행 관계는 [curriculum.md](curriculum.md), 실행 데이터는 `projects.js`를 확인하세요.

## 바뀐 게임 규칙

루트 [PRD](../prd.md)와 [완성 시나리오](../시나리오완성.md), [Vercel 제작 요약](../vercel%20시나리오.md)을 버전 2.1으로 동기화했습니다. 현재 익명 세로 레이스·4단계 커리큘럼·완료 관리가 기준입니다. 이후 사용자 지시가 문서보다 우선하며, 기능 변경 시 코드·문서·검증을 함께 갱신합니다. 이전 30초·단일 공·플리퍼 방식은 현행 요구가 아닙니다.

1. 첫걸음 8개 → 기초 확장 7개 → 연결과 배포 6개 → 실전 완성 3개 순서로 총 24개를 진행합니다. 현재 단계의 미완료 항목 중 선행 미션까지 완료한 것만 공으로 만듭니다. 단계 안에서 독립적인 미션은 섞고, 마지막 3개는 같은 서비스를 설계 → 구현 → 실사용·개선·재배포하는 순서를 지킵니다.
2. 공의 프로젝트 연결과 출발 위치를 섞습니다. 당첨 프로젝트를 미리 고르지 않습니다.
3. 여러 공이 위에서 쏟아져, 화면 약 5.5개 길이의 세로 코스를 달립니다. 카메라가 선두를 따라 내려가며 현재 구간만 보여줍니다.
4. 사용자가 방해봉을 옮기거나 주변 공을 밀어내 통과 순서에 영향을 줍니다.
5. **첫 번째로 출구를 통과한 공이 오늘의 미션이 됩니다.** 그 순간 레이스를 멈추고 정체를 공개합니다.
6. 나머지 공이 통과할 때까지 기다리지 않습니다. 이후 통과나 지연 콜백은 이미 확정된 미션을 변경하지 않습니다.
7. 명언과 프로젝트 정보를 공개하고 최근 미션 10건에 한 번 저장합니다.

현재 단계·선행 조건이 열린 수집 미완료가 있으면 다음 레이스를 시작할 수 없습니다. 결과 화면·내 프로젝트·시작 화면에서 직접 완료 체크하면 다시 열립니다. 후반/선행 미충족 이관 항목은 ‘선행 학습 대기’로 보류하고 차례가 열릴 때 잠금에 포함합니다. 보류 항목의 완료 체크는 비활성화합니다. 완료한 프로젝트는 후보에서 제외하며, 현재 단계 전체를 완료하면 다음 단계가 자동으로 열립니다. GitHub API → 서버 날씨 → DB 메모 → 로그인·권한의 선행 관계를 지키고, 전시관 배포는 연결과 배포의 나머지 5개 뒤에 열립니다. 이후 단계를 수동으로 먼저 선택할 수 없습니다. 마지막 공 1개도 실제 코스를 달려 미션을 받습니다. 24개를 모두 완료하면 레이스 대신 전체 완료 화면을 표시합니다.

일반 시작·자동 진행·재개·플레이 및 일시정지/통과 직전 URL 진입에도 동일한 잠금을 적용합니다. 새로고침 후에도 저장된 완료 상태로 진행 단계를 계산합니다. 완료를 해제하면 미완료로 돌아가 다시 레이스가 잠기며, 가장 앞선 미완료 단계부터 이어집니다.

점수, 30초 종료, 단일 공 재발사, 사전 무작위 당첨은 제거했습니다. 레이스 종료 시점은 첫 공의 실제 배출입니다. 충돌 계산의 세부 스텝 안에서 가장 이른 출구 통과 시각을 비교하며, 정확히 동률일 때만 임의 순서로 처리합니다. 익명성과 HARD 장애물 구성은 유지합니다.

## 방해하는 방법

- 마우스로 보드 안을 드래그: 라임색 방해봉을 원하는 위치로 이동
- 보드 안을 짧게 클릭: 클릭 지점 주변 공을 밀어내기
- 방향키 또는 WASD: 방해봉 상하좌우 이동
- Space 또는 ‘밀어내기’ 버튼: 방해봉 주변 공을 밀어내기
- ‘방해 멈추고 지켜보기’: 방해봉과 장애물을 열고 그대로 진행. 남은 공 중 새로 추첨하지 않습니다.
- 일시정지: 공·장애물·밀어내기 대기 모두 정지

방해 없이 지켜보기도 레이스를 실제로 진행합니다. 즉시 임의 프로젝트를 고르지 않습니다. 긴 지연을 피하려고 시뮬레이션 60초가 지나면 장애물을 열고, 멈춘 공에는 물리적인 힘을 가합니다. 공의 프로젝트 연결이나 생존 공을 바꾸지 않습니다.

## 게임 난이도 — HARD

학습 프로젝트의 난이도 선택과 별개로, 레이스 자체를 더 까다롭게 조정했습니다.

- 핀 8줄과 회전봉 4개, 좌우로 이동하는 범퍼 2개를 긴 코스에 분산
- 네 번째 구간의 폭 130 통과문, 결승 전 가속 구간과 폭 140의 결승 통로
- 방해봉 길이 132 → 92, 이동 속도 제한으로 위치를 미리 잡아야 함
- 밀어내기 반경 155 → 105, 대기 0.65 → 1.4초, 버튼에 재사용 대기 표시
- 이동·회전하는 장애물은 실제 표면 속도로 공에 힘을 전달

수치는 보드 내부 물리 좌표 기준입니다. 결과를 미리 정하거나 공을 교체하지 않습니다. 빠르게 끝내고 싶으면 ‘방해 멈추고 지켜보기’로 장애물을 열 수 있습니다.

## 세로 추적 레이스

전체 월드는 폭 600, 높이 3,600이고 카메라는 높이 650 구간만 보여줍니다. 출발과 결승을 한 화면에 축소해 표시하지 않습니다. 시작 → 회전 지대 → 난기류 → 움직이는 관문 → 마지막 질주의 다섯 구간으로 구성합니다.

카메라는 선두의 진행에 맞춰 부드럽게 하강하고 코스 바깥으로 벗어나지 않습니다. 나머지 공은 화면 밖에서도 같은 물리 월드에서 계속 움직이며, 뒤에 있는 공의 개수만 익명으로 안내합니다. 진행률은 가장 멀리 진행한 지점 기준입니다.

방해봉은 카메라 화면을 따라 이동합니다. 포인터 입력에는 카메라의 월드 좌표를 더해 실제 클릭 지점에서 충돌·밀어내기를 처리합니다. 배경 격자·구간 표식·공의 잔상·속도선·밀어내기 때의 가벼운 흔들림으로 속도감을 표현합니다. 모션 줄이기에서는 장식 효과를 끄고 기능에 필요한 카메라 추적은 유지합니다.

코스가 길어져도 단순 대기를 늘리지 않도록 기본 낙하와 마지막 질주의 속도를 높였습니다. 첫 결승선 통과 즉시 결과를 공개합니다. 레이스 중에는 긴 소개를 구간·진행률 패널로 바꾸고 보드를 브라우저 높이에 맞춥니다.

## 익명성

모든 공의 색·크기·외형이 같고 이름·고유 번호·태그·툴팁·프로젝트별 접근성 라벨이 없습니다. 첫 공이 통과한 뒤 그 공의 정체만 결과로 공개합니다. 화면에 제공되는 물리 스냅샷에는 프로젝트 ID가 없고 내부 연결은 엔진의 private Map에서 보관합니다.

이는 플레이 화면에서 공의 정체를 알아볼 수 없게 하는 설계입니다. 브라우저 개발 도구로 클라이언트 프로그램을 분석하는 것까지 차단하는 보안 기능은 아닙니다.

## 화면 목업

### 오늘의 명언 24개

`quotes.js`에서 남성 애니 캐릭터 21명과 UFC 선수 3명, 총 24명의 실제 대사·인터뷰 발언을 관리합니다. 드래곤볼·강철의 연금술사·하이큐·슬램덩크는 포함하지 않습니다. UFC 구성은 정찬성, 더스틴 포이리에, 맥스 할로웨이입니다. 24명마다 서로 다른 인물 일러스트와 한마디가 있습니다.

한국어 문구는 원문의 짧은 발췌를 자체 번역한 것으로 공식 한국어 자막이 아닙니다. 카드 아래 ‘원문과 출처 보기’에서 원문·출처 링크·장면 맥락·자료 종류를 확인할 수 있습니다. 공식 애니 사이트·원작 회고·라이선스 상품 자료·인터뷰를 우선 사용했고, 샹크스·기유는 매체 보도, 무면허 라이더·아르민은 2차 자료라는 점을 구분해 표시했습니다. 영상 전체를 대조하거나 모든 문구의 애니메이션 회차·한국어 자막을 검증한 것은 아닙니다. 확인하지 않은 회차 번호는 넣지 않았습니다. 전체 출처 목록은 `sources.md`에 있습니다.

프로젝트 24개에 인물·명언 24개를 중복 없이 1:1로 고정 연결합니다. `projects.js`의 `quoteId`가 연결 기준입니다. 프로젝트가 결정되면 그 프로젝트의 명언과 그림을 함께 표시하며, 새로고침·재플레이·기록 조회·프로젝트 상세에서도 같은 연결을 사용합니다. 생피에르·조제 알도·탄지로를 제외했고, 해당 프로젝트에 사스케·가이·로를 연결했습니다. 남는 명언 없이 전체 24개가 모두 배정되어 있습니다. 기존에 무작위로 저장된 명언 ID는 기록을 읽을 때 프로젝트의 고정 연결로 맞추며 프로젝트와 날짜는 보존합니다. 결과 화면을 새로고침하면 최근 저장 결과를 복원합니다. ‘오늘의 명언’에서 24개 주제 버튼으로 모든 문구를 미리 볼 수 있고, 관리자 ‘인물 · 명언’에도 24개 카드가 표시됩니다. 기존 창작 문구를 실제 발언으로 교체했으므로 기록 저장 공간도 분리했습니다. 프로젝트 수는 24개, 한 판의 공 수는 현재 단계와 선행 조건을 모두 만족하는 미완료 프로젝트 수입니다. 실전 완성은 1개씩 순서대로 열립니다. 24명은 명언의 인물 수이며 공 수를 뜻하지 않습니다.

사용자 화면 13개와 관리자 목업 4개를 왼쪽 메뉴로 전환합니다. ‘통과 직전’ 메뉴는 한 공이 출구 근처에 있는 상태를 바로 확인하기 위한 미리보기입니다. 공을 실제로 통과시켜 첫 도착 즉시 결과 공개를 확인할 수 있습니다. 메뉴를 통해 직접 여는 결과 화면은 시안용이며 실제 레이스 당첨으로 저장하지 않습니다.

### 내 프로젝트 · 완료 관리

실제 레이스에서 뽑은 프로젝트는 왼쪽 ‘내 프로젝트’에 자동으로 모입니다. 최근 결과 10건과 별도로 최대 24종 전체를 보관합니다. 첫 추첨일과 최근 추첨일을 저장합니다. 결과 화면·관리 목록·잠금 화면에서 완료 체크·해제가 가능하며 전체·미완료·완료 필터와 단계별 완료 현황을 표시합니다. 완료한 프로젝트는 재추첨하지 않습니다. 이전 버전의 중복 추첨 이력과 횟수는 유지합니다.

현재 저장 키는 `project-pinball:curriculum4:collection:v1`입니다. 첫 진입 시 이전 `project-pinball:collection:v1`에서 공통 미션만 이어받고, 이전 원본은 그대로 보존합니다. 폐지된 미션의 ID를 새 콘텐츠에 재배정하지 않습니다. 처음 사용하면 현재 남아 있는 실제 최근 기록도 수집하며, 화면용 샘플은 수집하지 않습니다. 새로고침해도 상태를 유지하지만 브라우저 데이터 삭제나 다른 브라우저·기기에는 이어지지 않습니다. 저장 실패 시 현재 화면에만 반영된다는 안내를 표시합니다.

### 기능 → 기술 → 배울 지식

24개 프로젝트 모두 `learning`에 두 가지 구현 예시를 담았습니다. 각 예시는 만드는 기능·사용하는 기술·얻는 지식의 세 항목으로 구성합니다. 결과 화면에서는 바로 표시하고, 내 프로젝트에서는 펼쳐 볼 수 있습니다. 예를 들어 프로필 카드는 HTML·CSS로 소개와 사진을 배치하면서 구조와 디자인의 분리를 배우고, 링크·미디어 쿼리를 적용하면서 페이지 연결과 반응형 배치를 배웁니다.

관리자 화면은 콘텐츠 구조 확인용이며 실제 관리 서버나 저장·배포 기능이 없습니다. 기록이 없을 때 기록 화면에는 샘플임을 표시한 예시가 나옵니다. 현재 결과 저장 키는 `project-pinball:curriculum4:history:v1`입니다. 이전 `project-pinball:roster27:v1`은 보존하며, 처음에는 공통 미션의 결과만 읽어옵니다. 이전 `race-mockup:v1` 기록은 새 문구에 잘못 연결하지 않도록 읽지 않습니다.

## 검증

### 예외 흐름 정책 (2.1)

- 기록의 판 ID·프로젝트/명언 ID·자료형·실제 달력 날짜·ISO 시각을 검사하고 중복 판을 제외합니다. 과거 결과는 날짜와 조회 종류를 함께 보관해 메뉴 왕복 후에도 그대로 표시합니다. 진행 중 판의 시작 날짜와 조회한 기록의 날짜는 별도로 관리합니다.
