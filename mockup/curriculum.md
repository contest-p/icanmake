# 4단계 바이브 코딩 커리큘럼

총 24개: 첫걸음 8개 → 기초 확장 7개 → 연결과 배포 6개 → 실전 완성 3개.

미완료 미션이 있으면 다음 추첨은 잠깁니다. 현재 단계에서 선행 미션까지 완료한 항목만 추첨합니다. 3단계의 전시관 배포는 그 단계의 나머지 5개 뒤에 열리고, 마지막 3개는 같은 서비스를 순서대로 이어갑니다. 아래 순서는 학습 목록의 표시 순서이며, 의존 관계가 없는 미션은 단계 안에서 섞입니다.

공통 습관: 최소 기능부터 만들기 → 직접 행동과 결과 확인 → 작은 변경과 Git 커밋. 완성 뒤에는 색 변경만 하지 않고 버튼 동작 또는 데이터 처리를 하나 바꿔 설명합니다. 자동 테스트와 수동 확인을 함께 연습합니다.

## 1단계 — 첫걸음 (8개)

화면·입력·데이터·상태가 연결되는 원리를 이해한다.

| 순서 | 미션 | 선행 미션 | 완료 기준 |
|---|---|---|---|
| 1 | 나만의 프로필 카드 | 이전 단계 완료 | 소개·사진·링크를 HTML로 배치하고 CSS로 꾸미기<br>화면 폭을 바꾸면 배치가 자연스럽게 바뀌는지 확인<br>소개 접기/펼치기처럼 동작 하나를 직접 바꿔 확인 |
| 2 | 글자 수 세기 | 이전 단계 완료 | 입력할 때마다 글자 수를 계산하고 초기화하기<br>공백 포함/제외를 전환하고 빈 입력도 확인<br>줄바꿈과 이모지를 어떤 기준으로 세는지 설명 |
| 3 | 다크 모드 스위치 | 이전 단계 완료 | 버튼으로 밝은 테마와 어두운 테마 전환<br>새로고침 후 선택한 테마 복원<br>저장값이 없거나 잘못되어도 기본 테마로 작동 |
| 4 | 랜덤 메뉴 추천기 | 이전 단계 완료 | 카테고리 선택 후 해당 메뉴 중 무작위 추천<br>후보가 0개·1개일 때도 올바르게 표시<br>메뉴 데이터를 직접 추가하고 결과 확인 |
| 5 | 용돈 계산기 | 이전 단계 완료 | 수입·지출 내역 추가·삭제와 잔액 계산<br>빈 값·숫자가 아닌 값·잘못된 금액 안내<br>내역 하나를 바꿔 합계가 맞는지 직접 검산 |
| 6 | 나만의 할 일 목록 | 이전 단계 완료 | 할 일 추가·완료·삭제가 각각 정확히 동작<br>새로고침 후 데이터와 완료 상태 유지<br>같은 이름의 항목 두 개를 ID로 구분해 수정 |
| 7 | 집중 타이머 | 이전 단계 완료 | 시작·정지·재개·초기화의 동작을 구분<br>시작 버튼을 연타해도 타이머가 중복 실행되지 않음<br>정지 후 재개와 지연된 화면 갱신에서도 남은 시간 확인 |
| 8 | OX 퀴즈 게임 | 이전 단계 완료 | 문제 진행·채점·최종 결과 표시<br>같은 문제에서 연타해도 한 번만 채점<br>재시작 시 문제 위치와 점수, 입력 상태 초기화 |

## 2단계 — 기초 확장 (7개)

데이터가 늘거나 예상 밖 입력이 들어와도 앱이 유지되게 만든다.

| 순서 | 미션 | 선행 미션 | 완료 기준 |
|---|---|---|---|
| 9 | 이미지 미리보기 | 이전 단계 완료 | 선택한 이미지와 가로세로 크기·용량 표시<br>잘못된 파일 유형과 취소 상황 안내<br>파일을 교체하거나 화면을 닫을 때 미리보기 자원 정리 |
| 10 | 북마크·읽기 자료 보관함 | 이전 단계 완료 | 자료 추가·수정·삭제와 제목 검색<br>태그 필터와 선택한 자료의 상세 보기<br>잘못된 주소를 안내하고 새로고침 후 자료 유지 |
| 11 | CSV 미리보기 | 이전 단계 완료 | 쉼표·따옴표·빈 셀이 포함된 CSV를 올바른 표로 표시<br>잘못된 파일과 파싱 오류를 안내<br>표시 행 수를 제한하고 실제 데이터와 비교 |
| 12 | 기억력 카드 게임 | 이전 단계 완료 | 카드 섞기·짝 판정·횟수·승리 표시<br>두 장을 확인하는 동안 다른 카드를 뒤집지 못함<br>재시작 시 지연 처리와 모든 카드 상태까지 초기화 |
| 13 | 습관 체크 달력 | 이전 단계 완료 | 날짜별 체크·월 이동·새로고침 후 저장 유지<br>월말과 12월→1월 이동에서 날짜가 맞음<br>윤년 2월 등 날짜 경계 사례 확인 |
| 14 | 지출 대시보드 | 용돈 계산기 | 기존 용돈 계산기의 데이터와 입력 기능을 이어서 사용<br>월별·분류별 합계와 차트 표시<br>기능 추가 후 기존 잔액 계산·수정·삭제도 정상인지 확인 |
| 15 | 드래그 칸반 보드 | 이전 단계 완료 | 카드 추가·수정과 칸 사이 이동<br>드래그와 버튼 이동이 같은 상태 변경을 수행<br>새로고침 후 카드 내용과 위치 유지 |

## 3단계 — 연결과 배포 (6개)

서버·DB·권한을 연결하고 문제를 확인·복구한다.

| 순서 | 미션 | 선행 미션 | 완료 기준 |
|---|---|---|---|
| 16 | GitHub 프로필 조회 | 이전 단계 완료 | 사용자 입력으로 API를 요청하고 프로필 정보 표시<br>로딩·성공·없는 사용자·호출 제한·통신 실패를 구분<br>빠르게 검색을 바꿔도 이전 응답이 최신 결과를 덮지 않음 |
| 17 | 서버를 거치는 날씨 앱 | GitHub 프로필 조회 | 브라우저가 내 서버를 거쳐 날씨 API 결과를 표시<br>API 설정을 환경변수로 관리하고 비밀 값은 브라우저·Git·로그에 노출하지 않음<br>서버 요청·실패 로그를 확인하고 로딩·오류·단위 처리 검증 |

## 4단계 — 실전 완성 (3개)

하나의 서비스를 설계하고 구현한 뒤 직접 쓰며 개선한다.

| 순서 | 미션 | 선행 미션 | 완료 기준 |
|---|---|---|---|
| 22 | 내가 쓸 서비스 설계하기 | 프로젝트 전시관 배포 | 누가 어떤 문제를 해결할 서비스인지 작성<br>핵심 기능 3개와 화면·데이터 구조를 정리<br>각 기능을 완료했다고 판단할 행동과 결과를 작성 |
| 23 | 설계한 서비스 구현하기 | 내가 쓸 서비스 설계하기 | 설계한 핵심 기능 3개를 동작하는 한 서비스로 연결<br>서버 DB 저장과 필요한 로그인·사용자별 데이터 분리 적용<br>빈 결과·저장 실패·권한 오류와 완료 기준을 직접 검증 |
| 24 | 실제로 사용하고 개선해 재배포하기 | 설계한 서비스 구현하기 | 실제 주소에 배포한 뒤 프로젝트와 메모를 직접 관리해보기<br>발견한 불편함을 기록하고 필요한 기능 하나를 선택해 변경<br>오류 수정·기존 기능 검사 후 재배포하고 실제 주소에서 확인 |

## 이어 만드는 결과물

- 용돈 계산기 → 지출 대시보드: 기존 코드와 데이터 구조를 확장합니다.
- 클라우드 메모 앱 → 메모 계정: 같은 앱에 인증·권한을 붙입니다.
- 버그 수리소: 기존 앱을 골라 재현 절차 → 실패 테스트 → 수정 → 회귀 확인을 수행합니다.
- 실전 완성: 프로젝트 진행 보드 하나를 설계 → 구현 → 실사용·개선·재배포합니다. 핵심은 프로젝트 추가·수정·삭제, 준비·진행·완료 이동, 프로젝트별 메모 3개이며 DB 저장과 사용자별 접근 제한을 연결합니다. 마지막에는 실제 필요를 느낀 검색·필터 같은 기능 하나를 추가합니다.

## 기존 기록

공통 미션은 기존 ID와 명언 연결을 유지합니다. 폐지한 독립 미션(로컬 메모 검색, 사전 조회, 읽기 자료 모음, 서버 시간 확인, 환경변수 연습, 계산기 테스트)의 ID를 다른 콘텐츠에 재배정하지 않습니다. DB 메모·로그인·앱 버그 수리·실전 3개에는 새 ID를 사용합니다. 기존 저장 공간은 보존하고, 공통 미션의 기록·완료 상태만 새 커리큘럼 저장 공간으로 이어받습니다. 상세 구현과 학습 설명의 기준은 `projects.js`입니다.
